# SQLite 调用面登记

本文是 W2/W3 改写的唯一输入清单。目的是把服务端对 SQLite 的依赖登记到文件与行，标明每项的影响、PG 替代方式和归属切片；本文只登记，不改代码。

扫描范围是 `src/**/*.rs`。生产代码指排除 `tests/`、`tests.rs`、`*_tests.rs`、`*test_support*` 之后的文件；测试代码只在计数对照表中出现。`src/store/*.rs` 的核对口径是 `rg -l 'sqlite|SQLite|sqlx' src/store --glob '*.rs'`，结果为 68 个文件；该查询漏掉只含 `json_extract`、不含 `sqlx` 字样的 `src/store/key_store_alert_events_cte.rs`，因此实际审计 69 个 store 模块。其中 49 个含本文登记的构造，20 个只含 `sqlx` 占位符、Row API、注释或测试脚手架。全部复现命令见文末。

## 切片定义与汇总

- `W2-core`：core schema 的业务真值、账本、配额、会话、作业与并发语义改写。
- `W2-obs`：observability schema 的请求日志、统计、告警投影与派生重建。
- `W2-triggers`：9 个 SQLite 触发器的 PG 承接，以及 HA outbox/trigger 退役。
- `W3-cleanup`：SQLite 运行时、探测、legacy schema 路径、维护二进制与构建清单删除。

| 切片          | 条目数 |
| ------------- | ------ |
| `W2-core`     | 25     |
| `W2-obs`      | 20     |
| `W2-triggers` | 34     |
| `W3-cleanup`  | 65     |
| 合计          | 144    |

条目数是第 1 至第 6 节表格的数据行数，每行末列只有一个切片；附录的模块核对表不计入。`W2-core` 的 25 条中有 4 条来自探测表，不是业务模块，目的是把被 core 迁移顺带删除的 schema 探测明确归口。

标量 `MIN/MAX` 计数（按括号深度判断二参调用，只扫生产）：

```sh
python3 - <<'PY'
import pathlib, re
root = pathlib.Path('.')
def is_test(p):
    return '/tests/' in str(p) or p.name in ('tests.rs',) or p.name.endswith('_tests.rs') or 'test_support' in p.name
def scalar(line):
    hits = 0
    for m in re.finditer(r'\b(MIN|MAX)\(', line):
        i, depth, commas = m.end(), 1, 0
        while i < len(line) and depth:
            c = line[i]
            depth += (c == '(') - (c == ')')
            commas += (c == ',' and depth == 1)
            i += 1
        if depth == 0 and commas >= 1:
            hits += 1
    return hits
calls = lines = 0
files = set()
for f in (root / 'src').rglob('*.rs'):
    if is_test(f):
        continue
    hits = [scalar(l) for l in f.read_text().splitlines()]
    n = sum(hits)
    if n:
        calls += n
        lines += sum(1 for h in hits if h)
        files.add(f)
print(calls, len(files), lines)
PY
```

输出 `72 19 71`，即 72 个调用、19 个文件、71 行。
